# Nested Meta2×Meta3: one physical CUDA graph with island AR3 and EP AR6

**Scope:** read-only architecture/design review against the live AC922 V61 source. No core edits, build, model load, or GPU use in this review.

## Verdict

**The desired graph is structurally feasible in `ggml-backend-meta.cpp` alone; no change to `allreduce-p2p.cu` is required.** The CUDA backend already dispatches `GGML_OP_ALLREDUCE` on an F32 contiguous node, and its node `op_params` carry the `ggml_cuda_p2p_ar *` communicator and rank. Thus a physical graph can contain dense island-A nodes with the A P2P3 handle, dense island-B nodes with the B P2P3 handle, and MoE-boundary nodes with the outer P2P6 handle.

It is **not** a direct concatenate of the outer `cgraphs_merged`: nested Meta disables that outer merge, while the inner Meta3 context materializes only the current outer subgraph's `cgraphs_merged/cgraphs_chunks`. A working path needs an outer-owned per-subgraph fragment cache (or a refactor that separates child graph preparation from dispatch), then composes those fragments into one graph for each of six physical backends. This is a scheduler/materialization change, not a new compute kernel or a DPA rewrite.

The lowest-risk first implementation is **hot-path opt-in with the current path as the cold/materialization fallback**. A normal nested dispatch visits all outer subgraphs and lets each inner Meta3 create its merged P2P3 fragments; immediately after each child call, the outer context snapshots the fragment's complete descriptor DAG into parent-owned storage. A raw list of child `ggml_tensor *` is not a snapshot: the child merged/chunk contexts are reset and those descriptor addresses are reused. When every island×subgraph×physical-rank snapshot matches the same root graph UID and child generations, the next dispatch can compose/capture one six-rank graph. The existing nested host P2P6 reduction remains the fallback for cold/incomplete fragments.

## Live source facts

V61's build manifest is `notes/V61-build.json` (`build_run_id=20261016T002602.434235Z`, `ggml/src/ggml-backend-meta.cpp` was changed since the earlier runtime). The source inspected on AC922 has SHA-256:

- `ggml/src/ggml-backend-meta.cpp`: `04f678f75adcde24571c32f8b9007301146b3c74e87db9a9019691f017e07b1a`
- `ggml/src/ggml-cuda/allreduce-p2p.cu`: `25d3619a3fbd518c06949698e2f886cd3066ea9690d39cd2dc54e907d5ddf0af`

Current ownership/dispatch structure:

1. `ggml_backend_meta_context` has per-direct-member `backend_configs`, `cgraphs_merged`, `cgraphs_chunks`, `ctx_merged`, `ctx_chunks`, one `p2p_ar`, and workers sized for the direct members (`ggml-backend-meta.cpp:3364-3465`). In the outer Meta2{Meta3A,Meta3B} case, `initialize_nested_gpu_ar()` discovers six physical leaves and creates a separate `nested_p2p_ar` (`:3484-3590` approximately); outer `p2p_ar` is deliberately not initialized when direct members are themselves Meta devices (`:3629-3700`).
2. The ordinary graph merge is gated by `backend_ctx->p2p_ar != nullptr`; it reserves the handle, synthesizes `GGML_OP_ALLREDUCE` nodes, binds their `op_params` with `p2p_ar_set_params`, rewires downstream sources, then chunks the merged graph (`:4935-5068`). This is the working inner Meta3 dense-TP route.
3. The outer path iterates `n_subgraphs`. For each `i`, it dispatches the two child Meta graphs, then calls `nested_gpu_allreduce(i)` at an outer PARTIAL boundary (`:5335-5465`, `:5468-5487`). That helper flattens the two three-leaf partial tensors, obtains the six-device submission cohort, reserves P2P6 as needed, and calls the cold host API `nested_p2p_ar_allreduce` (`:5367-5449`). The six-rank reduction is therefore currently outside the child CUDA graph.
4. Inner merging makes its result available as one or more `cgraphs_chunks[local_rank]` graphs per physical rank. Those vectors are overwritten as the child Meta context handles the next outer subgraph. The parent cannot wait until the end of the outer loop and then read every child's current graph; it must snapshot each fragment immediately after that child call.
5. The child does `ggml_reset(ctx_m)` before rebuilding its merged graph (`:4974-4978`) and `ggml_reset(ctx_c)` before rebuilding chunks (`:5048-5051`). This overwrites synthetic AR3 tensor descriptors in place. Keeping only the `ggml_cgraph *`, `nodes[]`, or a graph-owner token does not preserve their descriptor metadata. Each fragment must be copied into a parent-owned metadata arena before the next child subgraph can reset those contexts.
6. Existing merged graphs allocate synthetic graph/node descriptors from `ctx_merged` and reuse a deterministic allocation order across rebuilds to keep CUDA graph captures valid (`:4964-5020`). `cgraphs_chunks` are graph descriptors over those same node tensors and carry generated UIDs (`:5024-5068`).

CUDA operation contract:

- `ggml_cuda_p2p_ar_set_params()` stores the communicator pointer, communicator-relative rank, capacity, and zero-input flag in the synthetic node (`allreduce-p2p.cu:573-581`).
- `ggml_cuda_op_allreduce()` reads the handle from that node, uses `ar->n`, flags, staging pointers, and the rank-specific epoch, then dispatches the existing 1-shot/segmented/relay-six kernel on the current backend stream (`allreduce-p2p.cu:384-446`). The parsed node number is only used in stuck-wait diagnostics (`:105, :142, :295`).
- CUDA op dispatch and supports-op already include ALLREDUCE (`ggml-cuda.cu:3403-3405`, `:8717-8718`). Each synthetic node has its own communicator pointer, so two communicator objects in the same physical graph do not require a CUDA-side “current communicator” switch.

## Minimal implementation seam

Keep the change scoped to `ggml-backend-meta.cpp`; preserve `GGML_META_NESTED_GPU_AR` default-off behavior.

1. **Extend the outer nested context with only the graph plumbing it lacks:** dynamically resolve/store `ggml_backend_p2p_ar_set_params` for `nested_p2p_ar`; resolve a physical CUDA `graph_ready` callback; allocate five physical worker lanes plus a caller lane for six-rank graph submission; store a parent-owned flattened graph arena and per-root-UID fragment metadata. Do not flatten/own CUDA contexts; retain the existing six `nested_leaf_backends` in `[A0,A1,A2,B0,B1,B2]` UUID order.
2. **Cold fallback snapshots descriptor closures, not pointers.** In the existing `for (i...)` loop, after `ggml_backend_graph_compute_async(childMeta, child_cgraph_i)` returns, check that the child context has a successful P2P3 merge (`merge_tried`, exactly three per-rank chunk vectors, no NCCL-large external route). For each local rank, snapshot each ordered chunk's tensor descriptor DAG into a parent-owned arena before the child context advances to the next outer subgraph. Keep executing this call's existing P2P6 host reduction so fallback remains authoritative. If any inner graph is unmerged, NCCL-backed, asymmetric, or has an unprovable descriptor payload owner, invalidate the composite cache and use the existing path.
3. **Compose only after the full fragment set is present.** For each global rank, concatenate the parent-owned clones of A or B's saved inner chunks in outer subgraph order into one parent-owned `ggml_cgraph`; rebuild its visited hash and use counts from the source chunks. Existing island AR3 clones remain in sequence and retain their original communicator `op_params`. At each outer boundary where the current code sees both island outputs as `PARTIAL`, append one new in-place alias node (`type/ne/nb/data/buffer/view_src/view_offs` copied from the per-rank local partial, `op=GGML_OP_ALLREDUCE`, `src[0]=partial`, `COMPUTE` set), name it uniquely per outer boundary, and call `nested_p2p_ar_set_params(nested_p2p_ar, global_rank, ar6_node)`. Rewrite only following nodes in that physical graph whose source is that boundary partial to read the AR6 result. The boundary predicate must match `nested_gpu_allreduce()`; do not place a collective before MoE gate/GLU/down plus top-10 weighting has produced the final local contribution.
4. **Reserve before graph capture.** Scan every eligible outer boundary across both islands and all six leaves, validate F32/contiguous/equal byte count, compute maximum `ggml_nbytes`, and reserve the P2P6 handle once before making any flattened CUDA graph ready. A later reserve can relocate `stage[]` buffers captured as kernel launch args, so capacity growth must invalidate the flattened graph generation before recapture.
5. **Launch as one six-rank cohort.** Acquire the physical-device submit order for all six in the same deterministic order and maintain the existing physical stream-tail/event ordering. Enqueue `ggml_backend_graph_compute_async()` on all six physical backend contexts concurrently (one task per physical rank; do not call rank-by-rank and wait). Check readiness across all six ranks as a cohort; on cold/new shape, let every rank submit before any drain. A flat graph contains no outer chunks, so the existing chunk-level lockstep loop is not a direct fit; retain its cold-capture safety by grouping six launches and joining/draining only after all have been enqueued.
6. **Key and lease by the complete graph generation.** The cache key must include the outer `cgraph->uid`, every child-subgraph UID and merged/chunk graph UID in order, rank/topology order, and every communicator's reserve generation/capacity. A child context can run its first unmerged dispatch and then build its merged graph later under the same child cgraph UID, so UID alone is insufficient. Reuse the same parent graph/node descriptor addresses for a hot generation; do not issue a fresh `ggml_graph_next_uid()` on every replay. On root UID or child graph-generation change, drain old physical graph work, invalidate the flat graph and fragments before a child buffer or descriptor arena can be reset/replaced, then fall back until all child fragments are rebuilt. Outer graph rewriting must call the existing replay-mutation notification before publishing the new graph. Retain child graph-owner tokens and `tensor_arenas` generations for every borrowed `buffer/data/extra` payload; additionally reject a clone that points into a child-owned scratch buffer that can be replaced by `backend_config.bufs[i].reset()` unless that buffer's ownership is made generation-shareable. Existing owner leases and arena comments are at `ggml-backend-meta.cpp:3407-3413`, collection/replacement at `:4502-4508` and `:5076-5078`; the lease contract is documented in `ggml-meta-context-owner-private.h:68-97`.
7. **Leave numerical semantics unchanged.** The AR6 synthetic node uses the existing P2P6 handle and its exact rank order. Per-node `op_params` allow AR3-A, AR3-B, and AR6 in one cgraph. Keep the output data pointer aliased to the input tensor, as the current CUDA op asserts in-place operation. Do not clear the model's logical PARTIAL/local-partial producer metadata: current split-state queries use `assume_sync=false` for the producer boundary and `assume_sync=true` for source/layout reasoning; the allreduce is a graph execution boundary, not a replacement logical tensor.

## Descriptor ownership and bounded metadata cost

A fragment cache must clone tensor descriptors, not merely `nodes[]` pointers. `ctx_merged` is reset at `ggml-backend-meta.cpp:4974-4978` and `ctx_chunks` at `:5048-5051`; the synthetic AR3 descriptor at a given address can therefore hold different `op_params`, `src[]`, `data`, or `buffer` in the next subgraph. `graph_owner_lease` holds `owner_ref`s, not these `ggml_tensor` descriptors (`ggml-meta-context-owner-private.h:68-97`).

For each physical rank and composite root generation, allocate one parent-owned descriptor arena and a memoized `clone_tensor(source, source_generation)` routine:

- Allocate the destination descriptor first, insert it in the memo, then recurse through every `src[]` and `view_src`. This preserves shared DAG edges and supports self/cyclic source references. The memo key must include source tensor address **and** owning generation: stable source descriptors use their root/tensor-arena generation; child-generated merged/chunk descriptors use child Meta instance token, child cgraph UID, outer-subgraph index, and the merged/chunk context generation. An address-only memo is invalid because the child arena resets/reuses addresses.
- Copy the full plain `ggml_tensor` metadata (`type`, `ne`, `nb`, `op`, `op_params`, `flags`, `name`, `view_offs`, padding) into a parent-allocated descriptor; rewrite `src[]` and `view_src` to memoized clones. Keep `buffer` and `data` as borrowed aliases to the real physical allocations; do not copy payload bytes. During composition, keep a per-rank map from each original boundary descriptor/generation to its cloned producer, then redirect later subgraph edges to the AR6 clone.
- Build new parent `ggml_cgraph`s in node order with `ggml_new_graph_custom`, reinsert every cloned node in `visited_hash_set`, and copy source `use_counts` by looking up the source graph's visited hash. When inserting AR6, use the same producer/AR use-count convention as the existing merge (`p` count 1, AR output receives the original producer count) and rewrite future source edges before publishing the graph.
- Memoize across all fragments in the same root generation and rank, rather than cloning a separate recursive source closure per fragment. Treat stable root logical nodes as one generation across the full root graph; use a child merged/chunk generation discriminator only for synthetic descriptors that the child resets. This bounds metadata storage to the unique descriptor DAG per physical rank/root generation instead of repeated all-prior-layers clones (the naive per-fragment recursive strategy can grow toward O(layers²)).
- `extra` is opaque CUDA/backend payload in public `ggml_tensor`. The default safe gate is `extra == nullptr`; if a real fragment has non-null `extra`, flatten must decline unless the implementation proves and pins that exact payload owner for the entire graph generation. Likewise, retain explicit strong owner references for all borrowed buffer/data allocations. The outer child backend object alone is not enough if a rebuild can replace a scratch buffer through `backend_config.bufs[i].reset()`.

A prepare-only alternative can avoid copying descriptor DAGs, but it must freeze the **entire** child graph generation (per-backend `nodes[]` and `cgraphs`, tensor-arena descriptors, `ctx_merged`, `ctx_chunks`, owner refs, and backing buffers) behind a parent-held shared generation object. Freezing only `ctx_merged/ctx_chunks` is insufficient because child `backend_configs[j].nodes[]` are rewritten on rebuild. The current context stores these parts separately and resets them in place, so this refactor is more invasive than a bounded parent-owned metadata clone.

## Risks / hard gates

- **Single graph identity cannot be claimed from child cgraphs alone.** The root must cache per-`i` cloned fragments because each child Meta3 context only retains its current graph chunks; a raw pointer list becomes stale as soon as the child resets its arena.
- **Communicator memory is captured indirectly.** Although node `op_params` keep a stable communicator pointer, CUDA graph kernel arguments copy P2P stage/flags/epoch device addresses when the op is captured. Reserve the maximum first and invalidate the graph on any handle-buffer relocation.
- **Cohort execution is mandatory.** P2P kernels spin until peer ranks arrive. Six physical graph calls must be submitted concurrently under one sorted cohort/tail order. A sequential “call graph_compute and wait per GPU” path can deadlock.
- **Retain the inner path's safety gates.** `nccl_large_graph` intentionally clears `cgraphs_merged` to avoid duplicate collectives (`:4925-4930`); skip flatten unless both inner Meta3 contexts actually contain the in-graph P2P3 fragments. All six leaves and every EP boundary must pass the existing F32/contiguous/shape checks (`:5392-5407`).
- **Graph size / capture cost remains unmeasured.** One graph spanning the full root cgraph can be much larger than today's chunked island graphs. V61 no-alloc loader success does not establish graph capture memory, correct execution, or speedup.

## Smallest validation sequence for root's implementation

1. Host-side graph assembly assertion: one test graph with one dense island-AR3 boundary and one EP boundary must produce six ordered node streams; each stream contains the expected local AR3 nodes and exactly one AR6 node at the final EP partial boundary. Assert all three communicator identities/ranks explicitly, `src/view_src` edges point only into the parent arena, downstream sources point to the AR6 output, and child `ctx_merged/ctx_chunks` reset/reuse after snapshot cannot mutate the parent graph. Exercise memoization across adjacent fragments and confirm cloned-descriptor count grows with unique descriptors, not cumulative upstream closures.
2. Tiny no-model six-GPU CUDA fixture: compare flattened graph with the existing nested Meta3 + host P2P6 path using the same Q8/FP32 consumer inputs; exact in-place values, local canaries, no CPU tensor-get, and graph cold→hot replay. Do not add this work to a running model load.
3. V61 model: one bounded request first through cold fallback, then one same-UID hot graph; require native semantic/full-logit gates, all-six CUDA-graph-ready marker, same runtime build hash, graph node/AR3/AR6 counts, and no host P2P6 call on the hot dispatch. Only then measure decode/prefill.

No gain estimate is made here. If all gates pass, the mechanism removes per-outer-subgraph graph submission and host AR6 enqueue/synchronization; it does not remove dense island TP3 AllReduce or any six-rank AR6 bytes.
